📐 Normalization in EduTrack

1NF (First Normal Form):

Every column contains atomic values. Composite attributes like student name are split into first_name and last_name.

2NF (Second Normal Form):

No partial functional dependency. In enrollments, grades depend on the entire composite key (student_id, course_id, semester, academic_year).

3NF (Third Normal Form):

No transitive dependencies. students stores only dept_id instead of repeating dept_name and building.

🛡️ ACID Properties Implementation

Atomicity:

Enforced through SQLite transaction blocks (BEGIN TRANSACTION, COMMIT, ROLLBACK).

Consistency:

Guaranteed via Foreign Key constraints and schema CHECK constraints (e.g., gpa >= 0.00 AND gpa <= 4.00).

Isolation & Durability:

SQLite guarantees serialized/WAL transaction isolation and writes completed changes to disk log storage.

❓ Top 6 Viva Questions & Concise Answers

Q1: How do you handle the Many-to-Many (M:N) relationship between Students and Courses?

Answer: An associative entity (junction table) named enrollments is created containing foreign keys referencing students(student_id) and courses(course_id) along with descriptive attributes such as semester, grade, and status.

Q2: What is the purpose of the Triggers in your database?

Answer: We have implemented automated triggers including trg_after_enrollment_grade_update which automatically recalculates a student's cumulative weighted GPA whenever course grades are entered, and trg_after_student_insert which logs creation events into an audit_logs table.

Q3: What is the difference between a Database View and a Base Table?

Answer: A Base Table physically stores data records on disk. A Database View (such as v_student_transcript) is a stored SQL query that acts as a virtual table dynamically assembled at query time without consuming duplicate disk storage.

Q4: What is the role of Indexes in your project?

Answer: Indexes (like idx_students_roll and idx_enrollments_student) build B-tree search indexes over frequently searched columns, reducing time complexity from an $O(N)$ full table scan to $O(\log N)$ fast index search.

Q5: What is the difference between WHERE and HAVING clauses in SQL?

Answer: WHERE filters individual rows before any grouping is applied. HAVING filters aggregate groups after the GROUP BY clause has been computed.

Q6: What is a Correlated Subquery and where is it used?

Answer: A correlated subquery is a subquery that depends on values from the outer query. In our project, it is used to determine the top-ranking student within each individual department.
